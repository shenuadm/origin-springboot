# 单体模式与微服务模式开发指南

## 概述

origin-springboot 采用**模块化单体架构**，支持通过 Maven Profile 在单体模式和微服务模式间一键切换。

| 特性 | 单体模式 | 微服务模式 |
|------|----------|------------|
| 架构 | Servlet + Spring MVC | Spring Cloud Gateway + WebFlux |
| 服务注册 | 无 | Nacos |
| 配置中心 | 本地配置文件 | Nacos |
| Gateway | 嵌入式限流/日志组件 | 独立网关服务 (origin-gateway) |
| 限流 | RateLimitFilter (基于 Redis) | Sentinel + Gateway Filter |
| 部署 | 单 JAR 部署 | 多服务部署 |

---

## 一、单体模式

### 1.1 启动方式

#### 启动类

```
origin-web/src/main/java/com/cosmos/origin/web/OriginWebApplication.java
```

#### 启动命令

```bash
# 方式一：Maven 运行（开发推荐）
cd origin-web
mvn spring-boot:run -P monolith

# 方式二：运行打包后的 JAR
java -jar origin-web/target/origin-web-0.0.1-SNAPSHOT.jar --spring.profiles.active=dev
```

#### 配置文件

| 文件 | 作用 |
|------|------|
| `application.yml` | 主配置，默认激活 dev 环境 |
| `application-dev.yml` | 开发环境配置（数据库、Redis 等） |
| `application-prod.yml` | 生产环境配置 |

#### 端口

- 应用端口：**8081**
- API 文档：http://localhost:8081/doc.html

### 1.2 嵌入式 Gateway 组件

单体模式下，使用 `origin-gateway-spring-boot-starter` 提供的嵌入式 Gateway 功能：

#### 组件说明

| 组件 | 位置 | 功能 |
|------|------|------|
| RateLimitFilter | `gateway.filter.RateLimitFilter` | 基于 Redis 的请求限流 |
| AccessLogInterceptor | `gateway.interceptor.AccessLogInterceptor` | API 访问日志记录 |

#### 限流配置

```yaml
# application.yml
origin:
  gateway:
    enabled: true                    # 是否启用网关功能
    rate-limit:
      enabled: true                 # 是否启用限流
      default-limit: 100            # 默认限流阈值（每秒请求数）
      time-window: 1                # 限流时间窗口（秒）
      limit-message: "请求过于频繁，请稍后再试"
      # 特定接口限流配置
      # path-limits:
      #   /login: 10                 # 登录接口限流 10/s
      #   /register: 10              # 注册接口限流 10/s
    white-list:                      # 白名单路径
      - /swagger-ui
      - /v3/api-docs/**
      - /favicon.ico
      - /webjars/**
    black-list: [ ]                  # 黑名单（IP或用户ID）
```

#### 日志配置

```yaml
# application.yml
logging:
  level:
    com.cosmos.origin.gateway.interceptor.AccessLogInterceptor: INFO  # 开启日志
    # com.cosmos.origin.gateway.interceptor.AccessLogInterceptor: OFF # 关闭日志
```

#### 工作原理

```
请求 → RateLimitFilter (限流检查) → AccessLogInterceptor (日志记录) → Controller
```

- **限流实现**：基于 Redis + Lua 脚本实现分布式限流
- **日志实现**：使用 Spring Interceptor 记录请求参数、响应结果、耗时等信息
- **配置禁用**：通过 `spring.cloud.gateway.server.webflux.enabled: false` 禁用响应式 Gateway，避免与 Spring MVC 冲突

### 1.3 模块开关

> ⚠️ **注意**：application.yml 中的 `origin.module.*` 配置是**模板占位符**，实际值由 Maven Profile 打包变体决定，**无需手动修改**。

#### 工作原理

```
application.yml 模板                    打包后结果
───────────────────                   ──────────────
admin: @module.admin@     ──────→     admin: true  (使用 -P monolith)
admin: @module.admin@     ──────→     admin: false (使用 -P no-comment)
```

配置中的 `@module.admin@` 是 Maven 属性占位符，打包时自动替换。

#### Maven Profile 对应关系

| Maven Profile | admin | comment | auth | oss | websocket | 说明 |
|--------------|:-----:|:-------:|:----:|:---:|:---------:|------|
| monolith | ✓ | ✓ | ✓ | ✓ | ✓ | 完整版（默认） |
| minimal | ✓ | ✗ | ✓ | ✗ | ✗ | 最小版 |
| no-comment | ✓ | ✗ | ✓ | ✓ | ✓ | 无评论模块 |
| no-websocket | ✓ | ✓ | ✓ | ✓ | ✗ | 无 WebSocket 模块 |

#### Maven Profile 打包变体

```bash
# 完整版（所有模块）
mvn clean package -P monolith -DskipTests

# 最小版（仅 admin + auth）
mvn clean package -P minimal -DskipTests

# 无评论模块
mvn clean package -P no-comment -DskipTests

# 无 WebSocket 模块
mvn clean package -P no-websocket -DskipTests
```

#### API 访问

单体模式下，所有 API 直接通过应用端口访问：

```
http://localhost:8081/admin/user/page
http://localhost:8081/comment/add
http://localhost:8081/login
```

## 二、微服务模式

### 2.1 架构说明

微服务模式下，系统由多个独立服务组成：

```
                                    ┌─────────────────┐
                                    │  API Gateway    │
                                    │  (origin-gateway)│
                                    │   端口: 8080    │
                                    └────────┬────────┘
                                             │
                    ┌────────────────────────┼────────────────────────┐
                    │                        │                        │
                    ▼                        ▼                        ▼
         ┌──────────────────┐    ┌──────────────────┐    ┌──────────────────┐
         │  origin-web      │    │  origin-auth     │    │  origin-admin    │
         │  (业务服务)       │    │  (认证服务)       │    │  (用户服务)       │
         │  端口: 8081      │    │  端口: 8082      │    │  端口: 8083      │
         └──────────────────┘    └──────────────────┘    └──────────────────┘
                    │                        │                        │
                    └────────────────────────┼────────────────────────┘
                                             │
                                    ┌────────▼────────┐
                                    │     Nacos       │
                                    │  注册/配置中心   │
                                    │  端口: 8848     │
                                    └─────────────────┘
```

### 2.2 启动方式

#### 启动顺序

```
1. Nacos（必须先启动）
   ↓
2. origin-gateway（网关服务）
   ↓
3. origin-web（业务服务）
```

#### 1. 启动 Nacos

```bash
# Docker 启动（推荐）
docker run -d --name nacos -p 8848:8848 -e MODE=standalone nacos/nacos-server:v2.3.0

# 访问 Nacos 控制台
http://localhost:8848/nacos
# 默认用户名/密码: nacos/nacos
```

#### 2. 启动 Gateway 网关

```bash
# 启动类
origin-gateway/src/main/java/com/cosmos/origin/gateway/OriginGatewayApplication.java

# 方式一：Maven 运行
cd origin-gateway
mvn spring-boot:run

# 方式二：运行 JAR
java -jar origin-gateway/target/origin-gateway-0.0.1-SNAPSHOT.jar
```

**Gateway 配置**：
- 端口：**8080**
- 自动注册到 Nacos
- 从 Nacos 读取配置：`origin-gateway.yaml`

#### 独立 Gateway 说明

微服务模式下，Gateway 作为独立服务运行，具有以下功能：

| 功能 | 说明 |
|------|------|
| 路由 | 基于 Nacos 服务发现自动路由 |
| 认证 | JWT Token 验证 |
| 限流 | 基于 Redis 的请求限流 |
| 跨域 | 全局跨域配置 |
| 日志 | 访问日志记录 |

#### Gateway 核心配置

```yaml
# origin-gateway/src/main/resources/application.yml
server:
  port: 8080

spring:
  application:
    name: origin-gateway
  cloud:
    nacos:
      discovery:
        server-addr: ${NACOS_SERVER_ADDR:localhost:8848}
      config:
        server-addr: ${NACOS_SERVER_ADDR:localhost:8848}
    gateway:
      server:
        webflux:
          globalcors:
            cors-configurations:
              '[/**]':
                allowedOriginPatterns: "*"
                allowedMethods: [GET, POST, PUT, DELETE, OPTIONS]
                allowedHeaders: "*"
                maxAge: 3600

jwt:
  secret: ${JWT_SECRET:xxx}
  tokenExpireTime: 120
```

#### 3. 启动业务服务

```bash
# 启动类
origin-web/src/main/java/com/cosmos/origin/web/OriginWebApplication.java

# 方式一：Maven 运行
cd origin-web
mvn spring-boot:run -P microservice

# 方式二：运行 JAR
java -jar origin-web/target/origin-web-0.0.1-SNAPSHOT.jar --spring.profiles.active=microservice,dev
```

**业务服务配置**：
- 端口：**8081**
- 服务名：`技术底座微服务版`
- 自动注册到 Nacos

### 2.3 开发模式

#### 配置文件差异

微服务模式使用 `application-microservice.yml`：

```yaml
# 关键差异
spring:
  main:
    web-application-type: reactive  # 响应式 Web
  cloud:
    nacos:
      discovery:
        enabled: true              # 启用服务注册
      config:
        enabled: true              # 启用配置中心
    gateway:
      server:
        webflux:
          enabled: true            # 启用 Gateway
```

#### 服务注册

微服务模式下，各服务自动注册到 Nacos：

| 服务名 | 描述 | 端口 |
|--------|------|------|
| origin-gateway | API 网关 | 8080 |
| 技术底座微服务版 | 业务服务 | 8081 |

#### API 访问

微服务模式下，通过 Gateway 统一入口访问：

```
http://localhost:8080/服务名/路径

# 示例
http://localhost:8080/技术底座微服务版/admin/user/page
http://localhost:8080/技术底座微服务版/comment/add
```

Gateway 会根据服务名路由到对应的服务。

#### 路由配置

Gateway 通过 Nacos 自动发现服务，无需手动配置路由：

```yaml
spring:
  cloud:
    gateway:
      server:
        webflux:
          discovery:
            locator:
              enabled: true
              lower-case-service-id: true
```

### 2.4 Sentinel 限流熔断

微服务模式下集成 Sentinel：

```bash
# 启动 Sentinel 控制台
docker run -d --name sentinel-dashboard \
  -p 8080:8080 \
  -e SENTINEL_USERNAME=sentinel \
  -e SENTINEL_PASSWORD=sentinel \
  bladex/sentinel-dashboard:latest

# 访问 Sentinel 控制台
http://localhost:8080
# 默认用户名/密码: sentinel/sentinel
```

## 三、开发建议

### 3.1 模式选择

| 场景 | 推荐模式 |
|------|----------|
| 个人开发/小型项目 | 单体模式 |
| 学习研究 | 单体模式 |
| 团队协作/微服务学习 | 微服务模式 |
| 生产部署（小型） | 单体模式 |
| 生产部署（大型） | 微服务模式 |

### 3.2 开发流程

#### 单体模式开发

1. 直接启动 `OriginWebApplication`
2. 开发完成后打包：`mvn clean package -P monolith -DskipTests`
3. 部署单 JAR 即可

#### 微服务模式开发

1. 先启动 Nacos
2. 启动 Gateway：`OriginGatewayApplication`
3. 启动业务服务：`OriginWebApplication`（激活 microservice profile）
4. 通过 http://localhost:8080 访问 API
5. 可按需启动更多微服务

### 3.3 注意事项

1. **数据库和 Redis**：两种模式共享同一套数据库和 Redis，无需额外配置
2. **配置同步**：微服务模式下，部分配置会从 Nacos 读取，注意配置一致性
3. **端口占用**：确保 8080、8081、8848 端口未被占用
4. **开发效率**：日常开发推荐使用单体模式，微服务模式适合团队协作或学习

### 3.4 Gateway 对比总结

| 维度 | 单体模式 | 微服务模式 |
|------|----------|------------|
| **形态** | 嵌入式组件 | 独立服务进程 |
| **依赖** | origin-gateway-spring-boot-starter | origin-gateway 模块 |
| **实现** | Servlet Filter + Interceptor | Spring Cloud Gateway (WebFlux) |
| **端口** | 复用 8081 | 独立 8080 |
| **路由** | 无（直接访问） | 基于 Nacos 自动发现 |
| **认证** | JwtAuthenticationFilter (Servlet) | JwtAuthGatewayFilter (WebFlux) |
| **限流** | RateLimitFilter (基于 Redis Lua) | 自定义 Gateway Filter |
| **配置** | application.yml | Nacos 配置中心 |

#### 设计思路

- **单体模式**：采用嵌入式方案，避免引入额外进程，简化部署
- **微服务模式**：采用独立 Gateway，符合微服务架构规范，支持服务治理
